---
title: Troubleshooting
description: Known limitations of rivu and how to work around them.
---

These are the current limitations. Each one has a workaround.

## generate() throws "The string contains invalid characters"

A value in a CDATA field that contains the sequence `]]>` makes `generate()`
throw `The string contains invalid characters`. CDATA cannot contain its own
terminator. Fields that are always CDATA, such as `title` and `description`, are
the most likely to hit this, as are any fields that contain markup.

Sanitize input before you pass it in. Entities do not help here, because CDATA
is not parsed, so `]]&gt;` would reach readers as literal text. Break the
sequence instead:

```ts
const safe = (value: string): string => value.replaceAll("]]>", "]] >");
```

The sequence is rare in prose. It usually comes from code samples in a post
body, where the extra space is harmless.

## Invalid dates are written as "Invalid Date"

If you pass an invalid `Date`, such as `new Date("garbage")`, rivu writes
`Invalid Date` into the element. It does not throw.

Check dates before you build the feed:

```ts
const date = new Date(input);

if (Number.isNaN(date.getTime())) {
  throw new Error(`Invalid date: ${input}`);
}
```

## image, skipHours, skipDays and textInput

`image`, `skipHours`, `skipDays` and `textInput` are accepted by the types but
are not yet serialized to the nested form RSS 2.0 requires. For example,
`<image>` needs `<url>`, `<title>` and `<link>` children, and `<skipHours>`
needs `<hour>` children. This is tracked in
[GitHub issue #140](https://github.com/jarmos-san/rivu/issues/140), with a fix
in [PR #145](https://github.com/jarmos-san/rivu/pull/145).

Avoid these four fields until the fix is released.

## author must be an email

RSS 2.0 requires `<author>` to be an email address. The `email (Name)` form is
accepted:

```ts
author: "jane@example.com (Jane Doe)";
```

rivu writes the value as given. A bare name such as `"Jane Doe"` is valid XML
but validators flag it.
